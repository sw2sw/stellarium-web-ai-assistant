# 时间控制接口

时间控制使用星图引擎的模拟时钟，不是操作系统时间。控制当前时刻与设置时间倍率是不同操作；命令执行后必须读取引擎状态核对结果。

## 命令

```json
{"type":"set_time_speed","factor":1000}
{"type":"set_time_speed","factor":1000,"simHours":24}
{"type":"set_time_speed","factor":0}
```

| 字段 | 含义 |
|---|---|
| `factor` | 必填数值。0为暂停，1为实时，正值向前，负值倒放。 |
| `simHours` | 可选的模拟时长；到达目标模拟时刻后自动停表。 |

`simHours` 描述模拟时间，不是真实等待秒数。换算由代码完成，模型无需推算并填入另一套计时参数。

命令预检约束包括倍率范围、非零倍率下限、模拟时长上限与折算真实耗时上限。当前倍率绝对值上限为86400，非零下限为0.0001，模拟时长上限为100000小时，折算真实耗时上限为72小时。`factor: 0` 不能与 `simHours` 组合用于定时运行；错误类型、未知字段和超范围值会被拒绝。

实际校验以 `bridge.validateCommand()` 与 `packages/host-adapter/loader.js` 的命令规则为准。预检不改变模拟时间。

## 读回与自动停表

`bridge.readState().time` 提供 `speed`、`running`、`jumps` 等状态。命令读回可包含请求倍率、实际倍率、方向、起止时刻和自动停表信息。

- 设置新倍率会替换原来的自动停表计划。
- 显式设置模拟时刻会清理原来的停表计划，应检查对应读回。
- 自动停表基于引擎时钟检查，可能受到浏览器调度和检查间隔影响，不保证在目标毫秒精确停止。
- 不能仅根据模型文本或真实墙上时钟宣称模拟已走完指定时长。

## 控制提案的上下文检查

助手在提问时冻结上下文，并在回答到达、用户确认及批次执行期间检查当前状态。自己的命令允许改变的状态与其他并发变化须分别处理；发现相关上下文已变化时，不继续盲目执行后续命令。

`time.jumps` 是时钟跳变计数信号，不是操作者身份记录。它可以反映宿主界面、其他脚本或本桥接对时钟的写入：

- 桥接自己的显式时间写入会在命令返回前登记符合判据的跳变，并重新锚定采样基线，避免下一帧重复计数。
- 逐帧观测会比较引擎时间位移与倍率允许的位移；调度间隔和积分误差需要容差。
- 高倍率下的小幅跳时可能落入容差，后台或卡顿也会影响采样；该信号不是无遗漏的时间审计。
- 调用方应根据当前命令允许改变的字段判断上下文，不把所有计数变化都当成外部干预，也不全局忽略自身桥接写入。

## 接入与测试

先通过 `bridge.getCapabilities()` 检查命令白名单及 `features.timeSpeed`、`features.timeJumpSignal`，再按[能力参考](API-CAPABILITIES.md)完成预检、用户确认、执行与读回。

时间控制的提示参考由 `naming-reference.js` 提供。修改上限或提示规则时，应保持桥接、助手和参考资源一致。

相关回归入口：

- `tests/e2e/timeflow.mjs`：引擎时间倍率、方向、暂停和自动停表。
- `tests/e2e/client.mjs`：提案上下文与批次控制。
- `tests/reference/consistency.mjs`：参考资源与代码约束的一致性。

浏览器套件需要实际浏览器、依赖和独立的宿主副本，不使用生产数据目录。测试入口及参数见[源码导航](../README.md)与脚本说明；不要把一次短时停表检查等同于任意长时间运行保证。
